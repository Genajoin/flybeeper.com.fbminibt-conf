Техзадание для отдельного агента. Две связанные части:

- **A** — полноценно добавить прибор **FlyBeeper FANET Vario**, попутно переименовав его

- **B** — заменить «скачай файл и открой nRF Connect» на **прошивку прямо из браузера**

Всё, что здесь написано про железо и протокол, проверено на живом приборе 27.07.2026 —
это не выжимка из документации, а то, что реально работает и где реально ломается.

### Поведение, которое нужно описать в инструкции (изменено в 0.24.0)

- **Включение: удерживать кнопку 3 секунды.** Отпустил раньше — прибор снова засыпает.
  Всё удержание сопровождается тиками с нарастающей частотой. До 0.24.0 включало любое
  касание, поэтому в инструкции стоит явно про это сказать.
- **Выключение: удержание 3 секунды** во включённом состоянии. Тики, затем мелодия.
  Что именно произойдёт, зависит от настройки «не засыпать при BLE»: полное выключение
  либо режим «замолчать, но остаться на связи».
- **Короткое нажатие** — переключение громкости (0 → 1 → 2 → 3 → 0), подтверждается бипами
  по числу уровня.
- **Отмена**: если начал удерживать, услышал тики и передумал — отпусти. Громкость при этом
  не переключится.
- **Транспортный сон**: двойной сброс с паузой 1–2 с. Прибор перестаёт рекламироваться.
- **Авто-выключение** по бездействию, если задан таймаут.
- Прибор **играет мелодию на каждое подключение и отключение по BLE** — при отладке
  выглядит как «прибор всё время перезагружается».

## Часть A. Полноценное добавление прибора

### A1. Переименование SKU: `fbfanetvario` → `fbfv`

Прибор сообщает в DIS модель **`FBFV`**, а SKU в конфигураторе — `fbfanetvario`.
`resolveSku()` (`src/composables/useFirmwareUpdate.ts`) их не свяжет: `'fbfv'` не начинается

### A2. Прошивка

Файл уже положен: `public/firmware/fbfv/app_update.0.24.0.bin` (189 200 байт,

## Часть B. Прошивка из браузера (SMP over BLE)

### B1. Транспорт

Сервис `8d53dc1d-1db7-4cd3-868b-8a527460aa84`, единственная характеристика
`da2e7828-fbce-4e01-ae9e-261174997c48` — и запросы, и ответы. Запись —
`writeValueWithoutResponse`, ответы приходят через notify.

Прошивка собрана с `CONFIG_MCUMGR_TRANSPORT_BT_REASSEMBLY=y` и `BT_L2CAP_TX_MTU=498`,
так что упрёмся в MTU браузера, а не прибора. Chrome обычно согласует 512.
На время DFU прибор сам просит короткий интервал соединения (7.5–11.25 мс), поэтому
188 КБ уходят за десятки секунд.

### B2. Формат кадра

Восьмибайтовый заголовок, дальше CBOR:

```
байт 0  op      0=read, 1=read-rsp, 2=write, 3=write-rsp
байт 1  flags   0
байт 2-3 len    длина CBOR-полезной нагрузки, big-endian
байт 4-5 group  1 = image management, 0 = OS management
байт 6  seq     номер запроса, эхом возвращается в ответе
байт 7  id      команда внутри группы
```

Нужные команды:

| Что                          | group | id  | op    |
| ---------------------------- | ----- | --- | ----- |
| Состояние слотов             | 1     | 0   | read  |
| Пометить образ для установки | 1     | 0   | write |
| Загрузка куска образа        | 1     | 1   | write |
| Перезагрузка                 | 0     | 5   | write |

CBOR-полезная нагрузка загрузки: `{"image": 1, "off": <смещение>, "data": <байты>}`,
в первом куске дополнительно `{"len": <полный размер>, "sha": <sha256 образа>}`.
Ответ содержит `{"rc": 0, "off": <сколько принято>}` — следующий кусок слать с этого `off`.

Пометка: `{"hash": <sha256 образа>, "confirm": false}`. Именно `confirm: false` — это
режим «попробовать»: если новая прошивка не запустится, загрузчик вернёт старую.
`confirm: true` пропускает эту защиту, в приложении не использовать.

Идентификатор образа — **sha256 от всего файла `app_update.bin`**. Он же приходит в
состоянии слотов и по нему сверяется результат.

### B3. Последовательность

1. Прочитать состояние слотов (полезно показать, что стоит сейчас).
2. Залить файл в слот 1 кусками.
3. Пометить по sha256.
4. Прочитать состояние ещё раз и **убедиться, что `pending: true`** — без этого шага
   нельзя отличить «залилось» от «залилось, но не применится».
5. Перезагрузить прибор. Соединение разорвётся — это нормально.
6. Подождать ~15–20 с (загрузчик копирует образ), переподключиться и проверить: в слоте 0
   должен быть новый sha256 с `confirmed: true`.

Шаг 6 обязателен. Прошивка подтверждает себя сама, дойдя до конца инициализации; если
в слоте 0 оказался новый образ, но `confirmed: false` — значит она не запустилась, и
загрузчик откатит её на следующей перезагрузке.

### B4. Подводные камни — проверено на железе

- **Прибор держит одно BLE-соединение.** Пока подключено другое приложение, попытки
  выглядят как таймауты, а не как внятный отказ. В конфигураторе это как раз преимущество:
  шить надо **по уже открытому соединению**, не разрывая его. Отдельно подключаться не нужно.
- **Каждое подключение и разрыв прибор озвучивает мелодией.** Не открывать соединение ради
  каждой операции: за одну сессию делаются и заливка, и пометка, и перезагрузка.
- **Не подтверждать образ досрочно.** `confirm: true` вместо `pending` снимает защиту от
  отката — при неудачной прошивке прибор останется мёртвым и лечится только вскрытием.
- **Образ проверяется подписью.** Прошивки подписаны RSA-2048, загрузчик проверяет подпись
  при установке. Подменить образ через веб нельзя — чужой просто не запустится.
- **Прогресс показывать обязательно.** Заливка идёт десятки секунд, без индикатора это
  выглядит как зависание.
- **Что делать при ошибке `rc != 0`** в ответе: показать код и не продолжать. Частые случаи —
  слот занят предыдущим образом (нужно стереть, group 1 / id 5) или образ не влезает.
- Никогда не заливать `merged.hex` — он для прошивки по проводам. Только `app_update.bin`.

### B5. Как оформить код

Стратегия — уход от конфигуратора к единому приложению карт, поэтому модуль писать
**переносимым**: чистый TypeScript без Vue и Pinia.

```
src/lib/smp/
  transport.ts   обёртка над BluetoothRemoteGATTCharacteristic (write + notify, очередь)
  codec.ts       заголовок + CBOR
  image.ts       upload / state-read / state-write
  os.ts          reset
src/composables/useFirmwareFlash.ts   тонкая обёртка: прогресс, состояния, ошибки
```

Единственная зависимость модуля — объект характеристики. При переезде в приложение карт
он копируется целиком, переписывается только обёртка.

CBOR: полноценная библиотека не нужна, SMP использует плоские map. Либо свой кодек
(~100 строк на нужное подмножество), либо `cbor-x` (~10 КБ).

### B6. Куда встроить в UI

`src/pages/update/firmware/[sku].vue` уже показывает список версий со ссылками на скачивание.
Добавить рядом с последней версией кнопку «Обновить», активную только когда прибор
подключён и его SKU совпадает. Ссылку на скачивание оставить — она нужна для iOS Safari
и как запасной путь.

Состояния для UI: не подключён → подключён, обновление не требуется → доступно обновление →
заливка (проценты) → перезагрузка (ожидание) → успех / ошибка.

На iOS Safari Web Bluetooth недоступен в принципе; в конфигураторе уже есть баннер с
переходом в Bluefy, через него работает.
